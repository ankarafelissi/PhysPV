| Step | Rule and action | Rationale or limitation | Implementation |
| --- | --- | --- | --- |
| Scope | Apply sensor QC to PV power, air temperature, humidity, wind speed, wind direction, GHI and POA irradiance. Leave unused raw columns unchanged. | Rules apply to the local five-minute SOLETE file; second-level cleaning rules are not transferred directly. | `src/cleaning.py`: `TRAINING_COLUMNS` |
| Time grid | Sort timestamps; reject duplicates and off-grid timestamps; insert missing five-minute rows as NaN. | Preserve real time intervals so windows cannot bridge gaps. | `src/data.py`: `load_data` |
| Nonfinite values | Preserve NaN and replace positive or negative infinity with NaN. Do not interpolate or impute. | Avoid creating observations or using future information. | `clean_training_data`; flag `1` |
| Humidity | Treat stored humidity as a fraction; replace finite values below 0 or above 1 with NaN. Do not divide by 100. | The source documentation specifies a 0–1 scale despite the column's percent label. | Flag `2` |
| Joint wind/humidity dropout | When wind speed and humidity are both zero, set both to NaN. Preserve zero wind speed otherwise. | Conservative site-specific dropout handling; not a universal failure criterion. | Flag `4` |
| Wind direction | Convert exactly 360° to 0°; replace other finite values outside 0–360° with NaN. | Endpoints are equivalent, but arbitrary modulo correction cannot recover an uncertain aggregated direction. | Flag `8` for equivalent conversion; flag `2` for invalid values |
| Wind speed and temperature | Replace finite negative wind speed and temperature at or below −273.15°C with NaN. | Use physical bounds rather than unsupported quantile, standard-deviation or site-temperature thresholds. | Flag `2` |
| Midnight observations | Flag midnight air temperature, humidity, wind speed and wind direction for review; retain values unless another rule invalidates them. | Concentrated anomalies do not establish their cause or justify dividing values by two. | Review-only flag `16` |
| Irradiance and PV power | Flag negative values for review without changing them. Do not reject values solely by quantiles, nominal capacity or disagreement with Pac. | Nighttime zeros can be valid; negative irradiance can reflect sensor offset. Generic radiation QC limits are not validated here for five-minute POA. | Review-only flag `32` |
| Constant and zero values | Retain values unless a separate explicit rule applies. | Constant or zero readings alone do not establish sensor failure. | No automatic invalidation |
| Physical features | Compute Pac, Pdc, module temperature and cell temperature from cleaned POA, air temperature and wind speed; missing inputs remain invalid. | Invalid sensor inputs must not produce apparently valid derived features. | `src/data.py`: `pv_power_features` |
| Forecast windows | Retain grid rows; exclude windows with invalid required inputs or targets; use common eligible forecast origins across feature spaces. | Prevent gaps from being compressed and ensure comparisons use the same forecast population. | `src/data.py`: `prepare_data` and shared eligibility |
| Temporal splits and scaling | Use configured UTC date boundaries; diagnostic configurations may use chronological ratios. Fit Pearson screening and scalers on TRAIN only. | Prevent feature-selection and preprocessing leakage. | `partition_bounds`, `prepare_spaces`, `prepare_data` |
| QC flags | Use per-cell bit flags; flags can coexist. Flags `1`, `2` and `4` invalidate values; `8` converts an equivalent angle; `16` and `32` request review only. | QC uses fixed rules without fitting thresholds or consulting neighboring/future observations. | `src/cleaning.py`: `QC_CODES`, `clean_training_data` |
| Forecast target correction | Keep configured `correct_power` separate from sensor QC. With sensor cleaning enabled, do not fill missing measured power with Pac. | Physics-based target replacement defines a corrected forecasting target; it is not evidence that replaced meter readings were faulty. Set `correct_power: false` before a new run to forecast measured power directly. | `src/data.py`: target construction; `config/config.yaml` |
